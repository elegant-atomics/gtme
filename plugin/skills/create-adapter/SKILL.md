# Create an adapter

A vendor is one YAML file, no code, verified offline before its first
live call. The contract is generated by the binary; read it, do not
recall it.

**Preflight.** `gtme version`. `gtme init` if `~/.gtme` is missing.

## Steps

1. **Binding or process?** One request per record (or per page) with a
   fixed response shape → **binding** (YAML). Conditionals, several calls
   per record, OAuth, computation → **process adapter** (an executable,
   NDJSON in and out); `gtme help --agent` documents that protocol.
   `http/enrich` covers a one-off GET into one field with no
   credential declaration; a binding is for anything reused, priced, or
   keyed.

2. **Read the contract.**
   ```sh
   gtme help --bindings          # schema, discovery path, a reference binding, the fixtures rule
   gtme adapters                 # what is installed, and where
   ```
   Copy the nearest shipped binding (`spec/bindings/` in the repo, or
   the reference printed above) and edit. Id is `<vendor>/<operation>`;
   directory is `~/.gtme/adapters/<vendor>-<operation>/`.

3. **Write `binding.yaml`.** `needs` = the `{{record.*}}` placeholders
   in the request. `provides` = canonical field names where they exist
   (`email`, `email_status`, `headline`), `<vendor>.<name>` where they do
   not. Declare `credentials`, `auth`, `errors` (404 → `skip` for "not
   found"), `cost` (a `{{config.*}}` template if the price is
   plan-dependent), `freshness_days`.

4. **Fixtures: `fixtures/conformance.json`.** Preferred: one real,
   sanitized response per request, recorded live. Otherwise write it to
   the documented shape and say so in a `"note"` field; record a real one
   before any armed run. `match` is a substring of `"METHOD path"` **or
   of the full URL**, so per-record fixtures are a query value:
   `"match": "domain=acme.com"`. First match wins; put the catch-all
   last.

5. **Verify, then simulate.**
   ```sh
   gtme adapters verify <vendor>/<operation>     # schema + fixtures, offline; prints hosts and credentials
   gtme run one-step.yaml --simulate             # a pipeline that says use: <vendor>/<operation>
   ```
   Then hand to `/gtme:run-pipeline`.

6. **A new entity type** (records that are not person or company):
   `types/<name>.json` beside the binding, keyed on a URL (`"identity":
   [{"field": "url"}]`), fields with tier and normalization. The
   shipped `post.json` (`gtme help --agent`, registry) is the model. A
   traverse binding (`role: traverse`, `from`, `relation`) is how such
   records enter a run from people or companies.

7. **Share.** `CONTRIBUTING.md` in the repo. Install someone else's with
   `gtme adapters add github.com/<owner>/<repo>/<dir>@main`.

## Do not

- Present a hand-written fixture as a recording.
- Put a key anywhere but `gtme secret set`.
- Write logic into a binding; that is the graduation rule, and the answer is a process adapter.
